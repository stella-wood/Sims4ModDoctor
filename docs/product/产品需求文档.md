# Sims 4 Mod Doctor 产品需求

> 版本 0.16 · 2026-10-10 · 计划改名为 Sims4ModSieve  
> 0.15 及之前的完整版本见 [archive/产品需求文档-0.15.md](../archive/产品需求文档-0.15.md)

## 1. 产品是什么

Windows 上《模拟人生 4》的本地 Mod 整理与排错工具。不需要登录，扫描在本机完成，不上传任何文件。

首页两个入口：**重复文件检测**、**Mod 冲突检测**。可选第三个入口「一键体检」，依次运行两者、分标签展示结果。

两项功能互不依赖：范围设置、运行状态、历史结果各自保存；一项失败或取消不影响另一项；不要求先运行其中一项才能进入另一项。

目前只有一名真实测试者，正式支持范围仅 Windows 上的 Sims 4 PC 版。

## 2. 设计原则

- 界面按玩家要做的事组织，不按后端模块组织。后端可以共用扫描、解析等模块，但不能让它们变成玩家必须先完成的步骤。
- 默认用玩家能懂的话。TGI、哈希、调用栈放在可展开的详情或导出报告里。
- 能用合理默认直接满足玩家意图时，直接做，不展示系统推理过程。
- 扫描只读。修改文件只发生在玩家明确选择并确认之后。
- 「没发现问题」和「没能分析」分开统计，读不了的文件不算健康。
- 不承诺静态检查能发现所有运行时问题。

## 3. 重复文件检测

### 3.1 范围

- 可添加任意多个文件夹并逐个勾选／取消；取消勾选不删除记录。
- 默认推荐 Mods 文件夹，但可以只扫外部目录（下载、备份、待整理等）。
- 每个结果文件显示完整路径和它来自哪个扫描文件夹。

### 3.2 判定

内容完全相同（整文件 SHA-256）即为重复。文件名、目录、修改时间不参与判定。

### 3.3 父目录和子目录同时选择

例如同时选了 `D:\Mods` 和 `D:\Mods\家具`：

1. 每个实际文件只读一次。
2. `家具` 是重点范围；`Mods` 中除 `家具` 以外的部分是参照范围。
3. 「家具 ↔ 其他位置」的跨范围重复排在最前、默认展开；两边各自内部的重复作为次级结果折叠。
4. 同一组只出现在一个分区。

这一推断不向玩家解释，只体现在结果顺序上。

### 3.4 一键勾选

只勾选、不删除。每组保留恰好一份，其余勾上。保留顺序：

1. Mods 内的文件优先于外部目录
2. 目录层级更深的优先
3. 仍并列时按路径稳定地选一个（同一次结果中不会来回变化）

勾选后玩家可任意调整，再点「删除所选」才执行。组复选框在「按建议勾选」或「整组全选」时都显示为选中。

只用于整文件相同的组，不用于冲突结果。

## 4. Mod 冲突检测

默认范围是 Mods 文件夹，玩家可以只选其中的几个文件或子目录；没选的不会被加入比较。

内部四个子功能，在冲突检测页内用标签切换，不占首页入口。

### 4.1 健康检查（进游戏前）

各项检查逐步加入。每份报告列出本次实际运行了哪些检查，没运行的不能显示为「通过」。

| 检查 | 现状 |
|---|---|
| package 文件或索引结构损坏 | 底层已完成 |
| `.ts4script` 读不了 | 底层已完成 |
| 脚本模块同名碰撞：内容相同／不同／读不了 | 底层已完成 |
| 脚本放得太深（Mods 下超过一层子文件夹，游戏不加载） | 待做 |
| Tray（图库里的人家、地块）用到了哪些 Mod | 待做，需求说明另附 |
| Tray 缺了哪些 CC | 需要游戏本体资源清单，暂缓 |
| 依赖缺失、资料片需求、版本不兼容 | 待调研 |
| 覆盖了哪些原版资源 | 信息级；需要游戏本体资源清单 |

### 4.2 多项冲突

对所选范围：

- 找出同一资源（同一 TGI）出现在多个 package 里的情况，比较内容：**内容相同**／**内容不同，可能覆盖**／**没比完**（无法解压、超出上限等）。
- 同时对所选范围做完全重复检测，结果单独分区。

覆盖原版或互相覆盖不自动算作有害。没有做过游戏内实验之前，不推断哪个文件最终生效。

### 4.3 报错诊断（玩游戏之后）

读取游戏原生的 `lastException`、`lastUIException`；装了 MCCC 时额外读取 `mc_lastexception.html`。MCCC 不是必需。

展示证据和可信度。不能只凭文件修改时间断定是哪个 Mod 引起的。

动手实现前需要一批真实报错文件作样本。

### 4.4 二分排查

静态检查找不出原因时使用：

1. 软件把选定范围内的 Mod 分成两半，禁用其中一半。
2. 玩家进游戏看问题还在不在，回来点「还在」或「没了」。
3. 软件记住结果，继续缩小范围，直到定位到一个或几个文件。

可以把健康检查、冲突检测中的嫌疑文件排在前面，减少轮数。

要求：

- 任何时候可以中止；中止或完成后都能一键把本次禁用的文件全部恢复原样。
- 进度保存在 Mods 文件夹以外，软件关掉再打开可以继续。
- 禁用方式见 6.2。

### 4.5 结果分级

每条问题分开显示两个维度：

- 处理等级：必须处理／建议优先／可能影响／信息
- 可信度：已确认／高度疑似／可能相关／信息不足

默认列表只显示前三级。「信息」级（正常覆盖原版、依赖已满足等）只计入总数，点进单个 Mod 的详情才看得到。不为每个正常的 Mod 生成一条结果。

摘要示例：

```text
已完成检查 1,243 · 未发现需处理问题 1,216 · 需要查看 27 · 未完成分析 5
```

等级要结合上下文：同名脚本模块内容相同只是冗余，内容不同才需要优先查看。任何等级都不会自动删除或禁用文件。

## 5. 一键体检

依次运行重复检测和冲突检测。开始前显示两边各自将使用的范围，结果分两个标签。一项失败，另一项的结果照常保留。

## 6. 文件操作

### 6.1 删除

- 只删除玩家勾选的实际文件。删除进入 Windows 回收站，不提供永久删除。
- 确认窗只有一句「确定删除所选文件？」和「否／是」。
- 执行前后台复核文件是否在扫描后发生变化；变了就不删，要求重新扫描。
- 部分失败时逐项报告，不报成全部成功。
- 删除后提供最近一次批量删除的「撤回」：恢复到原路径；原位置已有同名文件时跳过该项，不覆盖。
- 冲突结果不能整条删除，要展开后选择具体文件。

### 6.2 禁用

让游戏不加载某个 Mod，但保留文件，随时可以恢复。二分排查使用；以后的「一键禁用」也用同一套。

- 方式待定，二选一：
  - 改名，在原文件名后加 `.disabled`，文件原地不动；
  - 移到 Mods 以外的专用文件夹，并记录原路径。
- 实现前需在真实游戏中确认禁用后的文件确实不被加载（对照 `Resource.cfg`）。
- 能列出当前所有被本软件禁用的文件，并一键全部恢复。
- 恢复时原路径已被占用则跳过并提示，不覆盖。

### 6.3 不做

修复 Mod、编辑 package 内容、自动下载或更新 Mod、自动删除或禁用文件。

## 7. 联网与隐私

- 默认不联网，不需要登录，不上传 Mod、路径、日志或报告。
- 检查更新只在玩家点击，或玩家在设置里自己开启「启动时检查」时联网，只请求最新版本号。
- 日志和导出报告中的路径可能带有 Windows 用户名。界面显示和复制时替换为 `<用户>`。

## 8. 设置页（第一版）

- 文件夹：游戏 Mods 位置（各功能共用）；以后加入 Tray、游戏安装位置
- 删除与禁用方式
- 更新：「立即检查」按钮；「启动时自动检查」开关，默认关闭
- 关于与反馈：版本号；报错日志直接显示并可一键复制；打开日志文件夹；GitHub 地址；许可证

以后再考虑：扫描时跳过指定文件夹、深色模式。

## 9. 平台与测试

正式支持：Windows 上的 Sims 4 PC 版；本机可访问的文件夹。

尚未验证：macOS、Linux／Wine／Proton、主机版、网络共享目录、其他代际的模拟人生。

功能状态按证据标注：自动测试通过／本机真实测试通过／多用户验证通过。代码能运行不等于正式支持。

扩大测试时需覆盖：不同 Windows 版本、EA app 与 Steam、被 OneDrive 重定向的文档目录、中文与长路径、机械硬盘、上千个 Mod 的集合、损坏文件与旧版脚本。

## 10. 待定

- 禁用采用改名还是移出
- 原版资源清单从本机游戏读取，还是使用预先生成的清单
- 冲突检测范围的选择粒度（文件／文件夹／分类）
- 撤回的有效期，以及切换页面后是否仍可撤回
- 一键体检如何展示两边各自的范围
